# WEB-TOOLS — web_search + web_fetch (built-in server tools)

**Status:** design (awaiting build)  ·  **Opened:** 2026-08-30  ·  **Owner:** Claude
**Follows:** CLAUDE-TOOLS (native tool use). See `docs/vendors/anthropic.md`.

## Why

The agent has no live-web ability — it can't check trends, competitor pages, or current facts.
Anthropic's **server-side** `web_search` + `web_fetch` tools add that with no new infra: Claude
calls them, Anthropic executes them and returns the result **inline in the same response** — they
do NOT go through our `execute()`/`policy.allow` dispatch.

## Probe-confirmed shape (live, Sonnet 5, 2026-08-30)

- Valid newest tags (no beta header): **`web_search_20260318`**, **`web_fetch_20260318`**.
- A search resolves inline: `content` = `[server_tool_use, web_search_tool_result, text…]`,
  `stop_reason=end_turn` (no client round-trip in the common case).
- Cost signal: `usage.server_tool_use = {"web_search_requests": N, "web_fetch_requests": N}`.
- One search added ~20k input tokens (results are billed as input) → `max_uses` matters.
- Results carry `encrypted_content` that must be echoed back verbatim on later turns or the next
  request 400s — our loop already appends response `content` verbatim, so this is preserved.

## Decision (operator, 2026-08-30): **On, capped**

Both tools ON by default; web_search bounded by a per-turn `max_uses` cap and metered into the
per-brand daily budget (INC-3).

## What changes (~3 files + tests)

### 1. `agent/loop/tools.py` — `server_tool_defs()`
Returns the enabled server tools from config:
```python
[{"type": "web_search_20260318", "name": "web_search", "max_uses": AGENT_WEB_SEARCH_MAX_USES,
  **({"blocked_domains": [...]} if blocked else {})},
 {"type": "web_fetch_20260318", "name": "web_fetch", "max_uses": AGENT_WEB_FETCH_MAX_USES}]
```
Gated by `AGENT_WEB_SEARCH_ENABLED` / `AGENT_WEB_FETCH_ENABLED`. These are NOT in the `TOOLS`
registry (no `fn` — Anthropic executes them), just extra defs appended to the API `tools` list.

### 2. `agent/loop/runner.py`
- `tool_defs = tools.tool_defs() + tools.server_tool_defs() + (mcp.tool_defs() if mcp else [])`.
- **`pause_turn` handling:** a long server-tool turn can stop with `stop_reason="pause_turn"`.
  Add a branch — append the assistant content and continue the loop (re-send to resume) instead
  of treating it as the final answer. Bounded by `max_steps`.
- Server `server_tool_use` blocks are NOT dispatched (only client `tool_use` blocks are) — the
  existing `[b for b in content if b.get("type")=="tool_use"]` filter already ignores them.

### 3. `analytics/cost/pricing.py` + `llm.py::_meter`
Bill web_search from `usage.server_tool_use.web_search_requests` at **$0.01/search** ($10/1k);
web_fetch is free. Add a `web_search_usd` term to `anthropic_cost` (env-overridable via a new
`COST_ANTHROPIC_WEB_SEARCH_USD`, default 0.01). Metered cost flows into `budget.check` (INC-3).

## Config flags (new, `config.py` or read in tools.py)
| Env | Default | Meaning |
|---|---|---|
| `AGENT_WEB_SEARCH_ENABLED` | `true` | offer web_search |
| `AGENT_WEB_FETCH_ENABLED` | `true` | offer web_fetch |
| `AGENT_WEB_SEARCH_MAX_USES` | `3` | per-turn search cap |
| `AGENT_WEB_FETCH_MAX_USES` | `5` | per-turn fetch cap |
| `AGENT_WEB_BLOCKED_DOMAINS` | `` | comma-list passed as `blocked_domains` |

## Verification
- Unit: `server_tool_defs()` gated by the flags + caps; `anthropic_cost` adds web_search cost;
  runner continues on `pause_turn`.
- **Live (real Sonnet 5)**: run the real loop with web_search on for a goal needing a live fact;
  confirm the transcript shows the agent used search and the meter records a `web_search_requests`
  (cost ≈ $0.01). Confirm the encrypted result round-trips (a follow-up turn doesn't 400).

## Risks / mitigations
- **Cost** — bounded by `max_uses` (3) + the per-brand daily budget gate (search cost is metered
  before the next step). Watch input-token growth (~20k/search) — capped by max_uses.
- **Policy** — server tools bypass `policy.allow`; we bound via flags + `max_uses` + optional
  `blocked_domains`, and they can only *read* (no publishing).
- **pause_turn** — verify the resume path live; guard against an infinite pause loop with
  `max_steps`.

## Out of scope (later)
code_execution (dynamic-filtering search auto-provisions it under the hood anyway), Files API,
context editing. `web_search_20260318` supports `response_inclusion` — not used yet.
